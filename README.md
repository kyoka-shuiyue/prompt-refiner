# prompt-refiner

[简体中文](README.md) | [English](README.en.md)

`prompt-refiner` 是一个模型无关的 AI 技能（Skill）：把你说得粗糙、零散、互相矛盾的请求，整理成一份清晰的"任务合同"，让 AI 明白终点在哪、护栏在哪，同时保留它自己选路的自由。

它可以在任何支持 `SKILL.md` 技能格式的 AI 编程助手或 Agent 中使用（Codex、Claude Code、Cursor 等），不绑定任何特定模型或客户端。

## 先看一个例子

你对着 AI 说：

> 帮我做个能搜本地文件的工具，最好快一点

这句话 AI 能做什么？用什么技术栈？"快"是打开快还是搜索快？要不要界面？AI 只能猜——猜对了万事大吉，猜错了你来回返工。

经过 `prompt-refiner` 整理后，AI 收到的是：

```text
目标：一个可以检索本地文件内容的命令行知识库工具，输入关键词，返回匹配文件和片段。
成功标准：在 1 万个文件的目录上，常见关键词检索 3 秒内返回结果；支持 txt / md / pdf 文本。
重要边界：只读取指定目录；不联网；不改原始文件。
停止条件：先交付可用的命令行版本；图形界面是后续可选项，不在本次范围。
```

注意区别：字没有变多多少，但**目标、验收线、边界、范围**都清楚了。AI 不用猜，你也不用返工。

## 它解决什么问题

跟 AI 提需求时，通常有两种翻车方式：

1. **说得太少**——"帮我优化一下性能"。AI 不知道基准是什么、优化到什么程度算完、能不能改接口，只能靠猜。
2. **说得太满**——为了防止 AI 乱来，把每一步都规定死。结果模型明明有更好的做法，却被你的流程捆住了手脚。

`prompt-refiner` 的答案是用**最小充分任务合同**同时避开两个坑：只补全真正影响结果的信息，其余交给模型自主判断。

模型越聪明，Prompt 越不需要替它规定每一步，更需要讲清楚四件事：

- **要什么**（目标）
- **做到什么程度算完**（成功标准）
- **什么不能碰**（重要边界）
- **什么时候停**（停止条件）

这四件事加上"哪些未决选择值得问一句"，就是任务合同的五个字段。工具、模块、工作流、实现步骤都是辅助信息——只有它们会改变合同本身，或你明确要求时才写进去。

## 为什么短而清晰的 Prompt 更有效

现在的模型不缺上下文窗口，缺的是注意力。这个判断有真实依据：

- Stanford 与 UNC 的论文 [Lost in the Middle](https://arxiv.org/abs/2307.03172)（TACL 2024）实测发现：相关信息埋在长文本中部时，模型表现明显下降，且上下文越长越严重。
- [Anthropic 工程博客](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)建议 prompt 应追求"完整描述期望行为的最小信息集"，不要把一堆规则和边缘案例塞进去让模型自己猜重点。

换句话说，模型越强，越不需要你替它规定每一步；它需要的是短、明确、可验证的指令。

同一个需求，两种命运。

直接扔给模型：

> 帮我优化一下这个网站的加载速度

模型只能猜：哪个页面？多快算快？能不能改代码？动不动依赖？方向猜错，整轮返工。

经过 `prompt-refiner` 整理后：

```text
目标：首页首次加载从 4.2s 降到 2s 以内。
成功标准：Lighthouse 性能分 ≥ 85；LCP < 2.5s；回归测试全过。
重要边界：只改前端资源与构建；不动后端接口；不换框架。
停止条件：先出基线测量报告；图片压缩加代码分割达标即停，不做过度优化。
```

字数没多几个，但模型不用再猜了——注意力全部落在可验证的目标上，而不是在一堆流程描述里找重点。

## 安装

### 方式一：一行命令安装到 Codex（全局）

```bash
npx -y skills add kyoka-shuiyue/prompt-refiner --skill prompt-refiner --global --agent codex --yes
```

需要 Node.js `22.20.0` 或更高版本。安装后请重启 Codex。

### 方式二：手动安装（适用于任何支持 SKILL.md 的宿主）

```bash
git clone https://github.com/kyoka-shuiyue/prompt-refiner.git
cd prompt-refiner
```

把仓库里的 `prompt-refiner/` 目录复制到你的 Agent 技能目录：

```bash
# macOS / Linux
cp -R prompt-refiner /path/to/your-agent/skills/
```

```powershell
# Windows PowerShell
$skillsRoot = "C:\path\to\your-agent\skills"
Copy-Item -Recurse -Force .\prompt-refiner (Join-Path $skillsRoot "prompt-refiner")
```

如果宿主不会自动检测技能，请重新加载或重启。不同宿主的技能目录位置和调用语法以其官方文档为准。

更新时，在本仓库运行 `git pull --ff-only`，然后重新复制这个技能目录。

## 使用方法

### 自动触发

支持隐式技能路由的宿主会根据技能描述自动加载它，你正常说话就行。

### 显式调用

完善一个粗糙的需求：

```text
使用 $prompt-refiner 完善这个请求：
做一个可以检索本地文件的知识库工具。
```

### 快捷口令

`prompt-refiner` 认识几个口令，用来控制输出方式：

| 口令 | 效果 |
| --- | --- |
| `纯prompt` / `只要prompt` | 只返回一个可直接复制的 Prompt 代码块，不附带任何说明 |
| `不要问` / `直接继续` | 不向你提问，用安全默认值补全歧义后直接执行 |

例如：

```text
$prompt-refiner 纯prompt：完善这个本地 AI 桌面工具的开发需求。
```

```text
$prompt-refiner 不要问，使用安全默认值，在当前仓库完成这个功能并验证结果。
```

### 它对四种请求的不同处理

| 你想要 | 它的行为 |
| --- | --- |
| 完善、改写、比较 Prompt | 返回可直接复制的完善版 Prompt，不替你执行 |
| 直接执行任务 | 澄清关键决策后，在授权范围内执行 |
| 问一个只读问题 | 直接回答，不强制套 Prompt 框架 |
| 请求说得有歧义 | 先安全查看，推断低风险默认值，确有必要才集中问一次 |

## 它是怎么工作的

1. **先判断你要什么**：Prompt、直接执行、只读回答，还是澄清。
2. **内部压测**：围绕五字段合同自问自答，不设固定问题数量，问到答案不再改变合同为止。
3. **能默认就默认**：低影响的歧义直接选合理默认值，不打扰你。
4. **只问值得问的**：答案会改变范围、权限、安全、成本或验收标准时，才集中提最多一轮 1-3 个问题，每个问题附推荐默认值。
5. **输出最小充分结果**：一份可复制的 Prompt、一个直接的回答，或一份执行合同。
6. **交付前自检**：完成标准是否可观察、授权是否清晰、规则是否自相矛盾、有没有多余的规定。

只有真正复杂、多阶段、需要恢复上下文的执行任务，才会写持久计划文件。明确的局部修改、只读回答和纯 Prompt 工作保持轻量。

## 常见问题

**问：它会把我的 Prompt 改得很长吗？**

不会。它的核心原则就是"最小充分"——只保留影响目标、验收、边界、停止条件的内容，删掉凑数的流程和模板化的空话。大多数情况下，精炼后的 Prompt 比原文更短、信息密度更高。

**问：它会连环炮一样问我一堆问题吗？**

不会。向你提问最多一轮、1-3 个，且只问"答案会实质改变任务"的问题。其余歧义在内部用安全默认值消化。

**问：它支持哪些模型或工具？**

任何支持 `SKILL.md` 技能格式的宿主都能用，包括 Codex、Claude Code、Cursor 等。技能内容是模型无关的：不依赖特定厂商的 API、工具组合或工作流，也不为不同模型维护独立版本。

**问：我用语音输入，经常说得颠三倒四，它能处理吗？**

可以。语音输入常见的转写错误、同音字、语序散乱、动词丢失，它会先重建你的真实意图再处理，而不是按字面歧义直接执行。"我把 X 改成了 Y"这类话也会先核实再当作事实。

**问：它和"让 AI 多问几个问题"有什么区别？**

区别在于**问题经过筛选**。让 AI 随便提问，它会问你一堆无关紧要的细节；这个技能先在内部把能默认的都默认掉，只把"选错了结果会完全不同"的决策留给你。

## 设计原则

- 任务合同优先于穷举规格。
- 可观察的成功标准优先于模糊质量要求。
- 安全默认值优先于不必要的追问。
- 重要边界优先于规定实现路径。
- 最新证据优先于过时假设。
- 可见决策和验证优先于隐藏思考链。
- 任务合同充分后立即停止扩写。
