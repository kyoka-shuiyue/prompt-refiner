# prompt-refiner

[简体中文](README.md) | [English](README.en.md)

`prompt-refiner` 帮你理清思路：辨认真正想完成的事，解决会影响结果的歧义和冲突，再把必要的目标、边界和完成条件表达清楚。

**当前版本：1.3.0。重点是理清已有意图，保留用户的范围和创作自由。** 明确任务直接执行，只有真正影响结果的信息缺口才值得补充或询问。它也支持创建、改写、点评和比较 Prompt。

技能以 `SKILL.md` 及配套文件发布，供兼容宿主加载。具体发现方式和调用语法由宿主决定；核心规则不绑定特定模型。

## 这次更新了什么

- **收窄触发范围**：不再因任务长、复杂、开放，或没有列验收标准就自动精炼。意图清楚的创作请求也默认直接执行。
- **减少额外流程**：移除技能自身强制写计划文件的要求，以及重复口令、内部模式标签和阶段检查规则。实现、计划与验证交回原任务工作流。
- **约束目标补全**：可以从已有目的整理出可观察的完成条件，但不能擅自增加功能、模块、业务承诺、固定指标或实现方法。
- **明确退出条件**：结果可辨认、必要边界明确、重大冲突解除后，结束精炼并继续原任务。缺文件、环境未知或技术失败本身不重新启动需求访谈。
- **修正提问和口令**：重大歧义给出 2–3 个具体选项；默认集中一轮，仍有实质冲突时可最小追问。“直接继续”沿用已确认目标；“不要问／你决定”表示在授权范围内委托选择。

完整说明见 [CHANGELOG.md](CHANGELOG.md)。

## 什么时候使用

| 请求的情况 | 处理方式 |
| --- | --- |
| 语言混乱，已经影响理解 | 结合上下文重建意图；明显转写错误直接修正 |
| 意图不明、前后矛盾，或不同理解会明显改变成品 | 先看已有证据，再提出具体解释供选择 |
| 方向明确，但无法判断最终交付什么 | 从已有目的补齐必要目标与完成条件 |
| 明确要求创建、改写、点评或比较 Prompt | 交付 Prompt 或点评，未经要求不执行其中的任务 |
| 明确任务、简单请求、意图清楚的自由创作 | 直接进入原任务流程 |
| 仅缺原文、文件、数据，或环境未知 | 查找或索取最小必要输入，不重新访谈意图 |

例如：

> 帮我把这份说明精简成一页，但每一段都必须逐字保留。

这里需要先理清冲突：是保留完整原文、另附一页摘要，还是允许删改原文？两种结果不同，值得问清楚。

而“做一张有海边氛围的活动海报，其他你决定”已经给出明确方向与创作自由，不需要再追问配色、字体、布局，也不应自行扩展活动内容。

## 保留的能力

需要精炼时，只把真正影响结果的事项讲清楚：

1. 最终要得到什么。
2. 满足什么条件才算完成。
3. 范围、事实、权限等重要边界。
4. 何时结束、询问、重试或停止。
5. 哪些未决选择必须由用户决定。

这些是检查角度，不是每次都要填满的表格。清晰的原要求无需重写；普通实现选择交给执行者。补充内容应与任务规模相称，不能为了显得完整而扩写。

## 安装与更新

若使用 `skills` CLI，可运行：

```bash
npx -y skills add kyoka-shuiyue/prompt-refiner --skill prompt-refiner --global --agent codex --yes
```

也可以手动获取仓库：

```bash
git clone https://github.com/kyoka-shuiyue/prompt-refiner.git
cd prompt-refiner
```

将仓库中的 `prompt-refiner/` 目录复制到宿主的技能目录。更新时先运行 `git pull --ff-only`，再同步该目录；按宿主要求重新加载技能。运行环境要求以安装工具与宿主文档为准。

## 使用方式

支持隐式技能路由的宿主可根据描述自动选用；也可显式调用：

```text
使用 $prompt-refiner 理清下面这个请求，保留我的范围，只处理影响结果的歧义：
[原始请求]
```

| 口令 | 行为 |
| --- | --- |
| `纯prompt` / `只要prompt` | 只返回一个可复制的 Prompt；若缺输入会使它不可用，先索取该输入 |
| `继续` / `直接继续` | 沿用已确认目标和授权继续；新出现的重大歧义仍需解决 |
| `不要问` / `你决定` / `自问自答后执行` | 在已授权的决策范围内选择合理默认值；不扩大权限 |

用户要求执行任务时，澄清完成后继续执行；用户只要 Prompt 时，交付后结束。技能不另设精炼批准步骤，也不要求创建计划文件。
